# Link registry

Every URL that goes in a description comes from here or from the live skeleton pull
(your channel's most recent description). **Never type a URL from memory and never guess a
repo path**: a dead link in the top block is the most visible possible mistake.

Filled by "apply my brand kit" (the fixed rows) and grown by you (the tables below).

---

## Fixed — in every description

| Slot | What | URL |
|------|------|-----|
| 1 (always first) | The offer (`backbone/offer.md`). The only CTA. | <<OFFER_URL>> |
| Follow block | Instagram | https://www.instagram.com/<<YOUR_IG_HANDLE>>/ |
| Follow block | TikTok | https://www.tiktok.com/@<<YOUR_TIKTOK_HANDLE>> |

The slot-1 line is **rewritten every video** to name what that video's viewer actually wants from
the offer (the specific thing from *this* build), then the same URL underneath. Look at the skeleton
for how the newest one reads.

Never in a description: anything listed under "not sold" in `backbone/offer.md` (e.g. an "apply"
link, a call-booking link, a DM-to-call CTA).

## A tool that isn't in this file

The script names something new (a repo, an app, a model). Then:

1. Search for the official source: the GitHub repo, the product's own domain. Not a blog post, not
   a listicle, not a mirror.
2. Open it and confirm it's the thing actually demoed in the video.
3. Put it in the draft with the URL visible, and flag it in chat as new:
   `new link — <Tool> → <url> (verify)`.
4. After the creator confirms, add a row to the table above so the next video reuses it.

If the search doesn't produce a confident answer, leave the block out of the draft and say which
tool needs a link. An empty slot is fixable in ten seconds; a wrong URL ships to every subscriber.
